## 为什么做这个博客

很多技术问题是在真实工作中临时遇到的：一个 Git 命令、一段 ECharts 交互、一次服务排查，或者一个新的 Agent 工具。ChatGPT 能快速给出答案，但对话结束以后，这些知识很容易散落在历史记录里。

这个博客的目标是把有复用价值的对话重新组织成文章，让一次问题解决过程变成以后可以搜索、引用和继续更新的知识。

## 发布流程

整个流程保持简单：

```text
ChatGPT 技术讨论
→ 整理为 MDX
→ GitHub 独立分支
→ Draft Pull Request
→ Vercel Preview
→ 在线检查
→ Merge
→ 正式发布
```

内容直接存储在 GitHub 仓库中，博客使用 Fumadocs 管理 MDX，Next.js 在构建阶段生成静态页面。

## 为什么保留 Preview

自动生成文章可以提高效率，发布前的在线检查依然很有价值。Preview 可以直接看到真实页面里的排版、代码块、目录、移动端效果和链接状态。

因此最终操作可以压缩成两个动作：

1. 在 ChatGPT 里说“发布成博客”。
2. 打开 Preview，看完后合并 PR。

## 后续

以后新增文章只需要向 `content/posts` 添加一个 MDX 文件。页面路由、目录、代码渲染和静态构建都由现有框架负责。
