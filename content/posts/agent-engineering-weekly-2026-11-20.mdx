## 本周结论

本周最值得深入的三个主题：

1. **Skills 开始拥有独立的质量门禁**：NVIDIA SkillEvaluator 让“Skill 能否被 Harness 加载、是否安全、是否真正提升任务完成率”变成可测试问题。
2. **Agent 工作台正在形成可操作的人工协作界面**：Plannotator 的计划批注、PR Review、会话与反馈设计值得直接研究。
3. **Agent 输出从对话流走向结构化事件与证据**：AG-UI 负责前后端交互事件；Open Code Review 把代码范围、规则和行级发现连接起来。

工程判断：下一阶段的 Agent 平台应把 **运行事件、人工审批、结果证据、质量评测** 放在同一个任务闭环里。

### 1. [NVIDIA/SkillEvaluator](https://github.com/NVIDIA/SkillEvaluator) · Skills / Evaluation / Security

**推荐 9.5/10 · 难度中高 · P0**

**定位与原理**：Agent Skills 的质量评估框架。Tier 1 检查格式、质量、许可证、敏感信息、脚本和 Harness 兼容性；Tier 2 检查语义重复；Tier 3 通过沙箱中的真实 Agent 运行，对比安装 Skill 前后的任务表现（Skill Lift）。项目支持 CLI 和 CI 集成，详见 [README](https://github.com/NVIDIA/SkillEvaluator/blob/main/README.md) 与 [评测文档](https://github.com/NVIDIA/SkillEvaluator/blob/main/docs/index.mdx)。

**本周期已确认提交（UTC 时间，均落在统计窗口）**：
- [11/19 21:03 UTC：补充 SkillSpector hook 超时测试](https://github.com/NVIDIA/SkillEvaluator/commit/490de6c086)。
- [11/19 20:50 UTC：修复循环符号链接情况下 SARIF 发现保留](https://github.com/NVIDIA/SkillEvaluator/commit/6abca0bd5c)。
- [11/19 20:22 UTC：为插件引入经审查的命令 hook 豁免](https://github.com/NVIDIA/SkillEvaluator/commit/14132c18b4)。

**工程价值**：把原先凭主观感受判断的 Skill 质量拆成可验证的静态质量、安全、可发现性、有效性与成本指标。适合给已有页面设计 Skill 增加 PR 检查。

**实践**：安装后先运行 `skillevaluator quality-check ./my-skill`，记录分数与具体发现；随后使用 `skillevaluator harness-check ./my-skill` 检查不同 Agent 宿主的加载兼容性。Tier 3 需要额外环境和凭据，先做固定测试任务与对照组。

### 2. [backnotprop/plannotator](https://github.com/backnotprop/plannotator) · Control Plane / Human-in-the-loop

**推荐 9.4/10 · 难度中 · P0**

**定位与原理**：为 Claude Code、Codex、OpenCode 等 Coding Agent 提供计划、批注、代码 Review 和人工反馈界面。将用户对计划或代码的意见整理为可回传的结构化反馈；它是研究 Agent 平台“等待人工处理”交互的优质参考。[README 与开发命令](https://github.com/backnotprop/plannotator)。

**本周期已确认提交**：
- [11/19 23:42 UTC：合并 Inbox 内联媒体相关 PR #3737](https://github.com/backnotprop/plannotator/commit/eed3f69fd1)。
- [11/19 22:43 UTC：合并 Show Me 功能相关 PR #3696](https://github.com/backnotprop/plannotator/commit/ad587d8159)。
- [11/19 22:09 UTC：合并语义相关修复 PR #3691](https://github.com/backnotprop/plannotator/commit/c2f23f7d0f)。

以上为合并记录，具体交互效果需结合 PR Diff 和实际运行验证。此前 [v0.28.62 Release](https://github.com/backnotprop/plannotator/releases) 发布于 11/12，属于上周期边界之前的背景，涵盖 Inbox 启动 Agent、模型与 effort 选择、团队规则等，本文不标记为本周发布。

**工程价值**：计划审批与代码审阅可共享“选择对象 → 批注 → 发送反馈 → Agent 继续 → 再次审核”的交互模型。建议重点阅读 [apps](https://github.com/backnotprop/plannotator/tree/main/apps)、[packages](https://github.com/backnotprop/plannotator/tree/main/packages)。

**实践**：设计一个任务卡，包含目标、运行阶段、变更文件、待人工问题、批准/修改/停止动作；将每条反馈关联到任务与具体代码位置。

### 3. [alibaba/open-code-review](https://github.com/alibaba/open-code-review) · Coding Agents / Evaluation / Security

**推荐 9.2/10 · 难度中高 · P0**

**定位与原理**：采用 Git Diff、确定性文件选择与规则解析，再结合 LLM 生成可定位到代码行的评审结果。提供 CLI、Skill 与 CI 集成；核心学习价值是“可控输入范围 + 规则 + 证据化输出”。[项目仓库](https://github.com/alibaba/open-code-review)、[Skill 工作流](https://github.com/alibaba/open-code-review/blob/main/skills/open-code-review/SKILL.md)、[Delegate 模式](https://github.com/alibaba/open-code-review/blob/main/skills/open-code-review-delegate/SKILL.md)。

**本周期已确认提交**：
- [11/19 07:28 UTC：新增 SQL Review 规则](https://github.com/alibaba/open-code-review/commit/55b4b311d6)。
- [11/19 02:00 UTC：修复 LLM Loop 的上下文压缩预算预留](https://github.com/alibaba/open-code-review/commit/445ad9dea3)。
- [11/19 07:51 UTC：GitLab CI 失败评审不再发布误导性的 LGTM](https://github.com/alibaba/open-code-review/commit/37ff307598)。

**工程价值**：这组变更体现代码审查 Agent 的关键可靠性问题：文件类型覆盖、上下文预算、准确报告失败、行级证据。尤其适合构建 AI 代码 Review 的质量门禁。

**实践**：准备含 SQL 注入风险、无风险 SQL、TypeScript 逻辑 Bug 的三个测试 PR，比较规则检查与模型评审结果，记录误报、漏报和定位准确率。

### 4. [ag-ui-protocol/ag-ui](https://github.com/ag-ui-protocol/ag-ui) · Agent UI Protocol / Runtime

**推荐 9.3/10 · 难度中 · P0**

**定位与原理**：标准化 Agent 与前端之间的事件流。支持运行生命周期、文本、工具调用、状态快照/增量和人工交互。前端可以通过同一事件模型连接不同 Agent Runtime。[README](https://github.com/ag-ui-protocol/ag-ui)、[协议与架构](https://github.com/ag-ui-protocol/ag-ui/blob/main/CLAUDE.md)、[Server Quickstart](https://github.com/ag-ui-protocol/ag-ui/blob/main/docs/quickstart/server.mdx)。

**本周期已确认提交**：

### 下周（11/23–11/27）延伸

1. 用 Prisma + MySQL 持久化 `Task`、`Run`、`Event`、`Approval`、`Evidence`；每个 Event 保留幂等键、时间戳和关联任务。
2. 将 Review 的结构化反馈送回 Worker；实现 `waiting_for_human → running` 状态转换，测试进程重启与重复消息。
3. 给页面生成 Skill 建立五条固定任务，对比启用/停用 Skill 的产出，并记录完成率、错误、时间与 Token 成本。
4. 将检查分成 PR 快速门禁与 Nightly 模型评测，输出一份可复用的工程设计说明。

**最小验收标准**：一个任务能流式显示事件、等待人工审批、接收修改意见后继续执行；重放事件不会重复审批；每次结果可定位到证据；Skill 检查有可比较的报告。
