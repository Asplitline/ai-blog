## 本周结论

本周学习主线是把 Agent 的工具、技能、上下文与执行状态变成可测试的工程契约。OpenSRE 的专用工具与缓存优化、Cursor 的插件结构、Stitch 的网页设计规范提取、Firecrawl 的状态管理形成四个互补案例。

## 三、能力层连接：可验证的 Agent Tool Workbench

建议沿用上期 Agent Review Workbench，新增工具契约和证据采集能力。

```text
Trigger / Task
  -> Policy + Mandate
  -> Plugin / Skill
  -> Typed Tool / CLI
  -> Evidence + Run Events
  -> Evaluation
  -> Human Review
```

| 层 | 参考 | 最小实现 |
| --- | --- | --- |
| Skills / Plugins | Cursor Plugins、Stitch | manifest、版本、输入输出契约 |
| Harness | OpenSRE、superpowers | 工具注册、稳定 Prompt、验证循环 |
| Runtime | OpenSRE、DeepSeek Superagent | Run 状态、重试、人工接管 |
| Context | Firecrawl | 来源、哈希、清洗、错误记录 |
| Evaluation | SkillEvaluator | 固定任务、对照组、结果报告 |
| Control Plane | AG-UI、Plannotator | 事件流、证据卡片、审批 |

建议为工具调用定义以下教学用结构（非任何仓库的原始接口）：

```ts
type ToolResult = {
  callId: string;
  status: "success" | "failed";
  evidence: Array<{ uri: string; digest?: string }>;
  error?: { code: string; retryable: boolean };
};
```

工具层负责执行结果与证据；Runtime 负责重试与状态转换；UI 负责让人理解并采取下一步行动。对于写操作，服务端独立校验授权和幂等键。
