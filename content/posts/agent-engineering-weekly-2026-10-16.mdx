## 一、Harness / Evaluation：Harness²

**做什么**：[google-research/harness2](https://github.com/google-research/harness2) 将 system prompt、guardrails、memory、tool guidance、subagents、skills、scripts、plugins 定义为八类可编辑 Harness 组件。任务内用 Propose → Probe → Compose 生成、试运行和组合改进；跨任务将证据和改进策略写入 Improvement Harness。模型权重保持固定。

**本周变化**：项目源码在 10 月上旬公开，10/20 再次受到技术社区关注。本期属于「新进入学习重点」，而非本周首次发布。README 中的 benchmark 增益来自作者实验，需要独立任务集复核。

**为什么重要**：Harness 改进可以用质量、成本、耗时、失败率和回滚结果衡量，覆盖工具选择、上下文、技能和插件配置。

**此前项目关联**：[DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 研究插件式执行，[OpenRig](https://github.com/mvschwarz/openrig) 组织现成 Coding Agent，[Superpowers](https://github.com/obra/superpowers) 提供人工设计的流程 Skill。Harness² 补上基于执行证据优化这些配置的方法。

**学习下一步**：运行仓库的无模型凭证 Demo；固定模型和测试任务，比较两版 Harness 的成功率、token、时延和失败类型。

## 二、Context / Provenance：Graphify

**做什么**：[Graphify-Labs/graphify](https://github.com/Graphify-Labs/graphify) 使用 tree-sitter AST 提取导入、调用、继承等关系，建立可查询的代码图。关系边标记为 EXTRACTED（直接提取）或 INFERRED（推断），支持 query、path、explain。

**本周变化**：10/21–22 的 0.9.94 相关提交改进 SQL 表跨文件合并、T-SQL 解析、MCP 模糊查询及跨仓库调用证据定位。[SQL 修复](https://github.com/Graphify-Labs/graphify/commit/b8d9f123) · [MCP 修复](https://github.com/Graphify-Labs/graphify/commit/c6d4c251) · [跨仓库定位](https://github.com/Graphify-Labs/graphify/commit/775ddb9d)。

**为什么重要**：Coding Agent 可通过结构化子图回答「这个 API 影响哪些页面」，并为结果提供来源位置。仓库宣称的 token 节省与正确性收益需要实测。

**此前项目关联**：[PageIndex](https://github.com/VectifyAI/PageIndex) 处理长文档定位，[context-mode](https://github.com/mksglu/context-mode) 管理工具输出，[Hindsight](https://github.com/vectorize-io/hindsight) 负责跨会话记忆。Graphify 补充代码结构检索。

**学习下一步**：选择现有 React 项目追踪 API → Hook → UI，对比 grep、Graphify 和 Agent 文件浏览，记录遗漏边、准确率、token 与耗时。

## 三、Context I/O / Gateway：Headroom

**做什么**：[headroomlabs-ai/headroom](https://github.com/headroomlabs-ai/headroom) 压缩日志、JSON、源码和 RAG 内容，提供 Proxy、Library、MCP 接口。CCR 在本地保留原文，支持按需恢复。

**本周变化**：[10/17 Turn Hook](https://github.com/headroomlabs-ai/headroom/commit/fbf7bc32) 支持 OpenAI Responses HTTP/WebSocket 请求改写；[10/16 计量提交](https://github.com/headroomlabs-ai/headroom/commit/2912b7b6) 记录每请求的节省量；10/21 修复缓存和流状态指标。

**为什么重要**：上下文压缩应同时检验 token、时延、关键错误行保留、恢复次数和任务成功率。

**此前项目关联**：与 context-mode 的输出筛选、Hindsight 的长期记忆、[LiteLLM](https://github.com/BerriAI/litellm) 的模型路由分别构成 Context、Memory、Gateway 接口。

**学习下一步**：用同一份混合 JSON、日志、代码输入比较原始、截断、Headroom、context-mode 四组，形成 A/B 表。

## 四、Skills / Developer Tooling：官方插件和领域 Skill

**Claude Plugins**：[anthropics/claude-plugins-official](https://github.com/anthropics/claude-plugins-official) 将 manifest、MCP、Commands、Agents、Skills 组织为可安装插件，并区分官方内部与第三方来源。本周 security-guidance 升至 [2.0.16](https://github.com/anthropics/claude-plugins-official/commit/1e25068c)，扩展 Windows 证书库异常等测试场景。值得研究名称迁移、依赖锁定、权限审查和更新兼容性。

**Android Skills**：[android/skills](https://github.com/android/skills) 按模型表现薄弱的 Android 开发任务维护 SKILL.md，支持 Android CLI 与 Agent 插件。本周 [10/21 v1.0.16](https://github.com/android/skills/commit/95ea931a1ad8f9b2be132ae0cfb2aad964d71118) 和 [Codex 插件修复](https://github.com/android/skills/commit/09a35383) 展示跨宿主维护。

**此前项目关联**：[cursor/plugins](https://github.com/cursor/plugins) 负责插件分发，[Impeccable](https://github.com/pbakaus/impeccable) 结合设计 Skill 与确定性检查，[K-Dense Scientific Skills](https://github.com/K-Dense-AI/scientific-agent-skills) 展示领域 Skill Catalog。建议为每个插件记录来源、版本、权限、依赖、测试样本。

## 五、Coding Agents / Runtime / Control Plane / Evidence

**Orca**：[stablyai/orca](https://github.com/stablyai/orca) 提供 Coding Agent 的 Task、Run、Worktree 与 Review。本周继续修复 [Session Resume](https://github.com/stablyai/orca/commit/f0450469)、[审批状态](https://github.com/stablyai/orca/commit/1ac2c6a8)、[Workspace 休眠](https://github.com/stablyai/orca/commit/41661e33)。核心学习点是 waiting approval、resuming、completed、sleeping 的状态转换及事件顺序，与 [Paperclip](https://github.com/paperclipai/paperclip) 的组织治理互补。

**REA**：[morluto/rea](https://github.com/morluto/rea) 通过 MCP/CLI 暴露 JavaScript、Android、原生程序分析，返回 Evidence、Coverage 和 Limitations。本周改进 [不可变证据读取](https://github.com/morluto/rea/commit/74ed67da) 和 [ADB 解析](https://github.com/morluto/rea/commit/15ec8e98)。可衔接 [iFixAi](https://github.com/ifixai-ai/iFixAi) 的独立审计与 [tester-army/e2e](https://github.com/tester-army/e2e) 的确定性回归。

**Ruflo**：[ruvnet/ruflo](https://github.com/ruvnet/ruflo) 10/22 扩展 [逆向分析插件](https://github.com/ruvnet/ruflo/commit/1b319145)，并补充 [安全修复](https://github.com/ruvnet/ruflo/commit/92731bc6)。通用 Harness 集成领域工具时，优先评估权限、结果可信度与执行预算。

## 六、持续跟踪：Agent-native CLI、Local Inference、Gateway

[HKUDS/CLI-Anything](https://github.com/HKUDS/CLI-Anything) 本周出现在七日榜单，延续「将现有软件封装成 Agent 可调用 CLI」方向；本次未核实到窗口内新增功能提交，保持 P2。[ai-memory](https://github.com/akitaonrails/ai-memory) 的跨 Agent Handoff 继续与 Hindsight 做对照。

Local Inference 保留 [llama.cpp](https://github.com/ggml-org/llama.cpp)、[Ollama](https://github.com/ollama/ollama)、[vLLM](https://github.com/vllm-project/vllm) 作为推理后端实验组。Gateway / Sandbox 继续比较 LiteLLM 的路由、[OpenShell](https://github.com/NVIDIA/OpenShell) 的隔离与 [Cloudflare OS](https://github.com/cloudflare/cloudflare-os) 的能力审批。

推荐的工程链路：Task → Run Config / Harness Version → Context Graph / Memory → Gateway / Policy → Tool Evidence → Approval → Independent Eval / Regression。使用 Run ID 串联证据和结果。
