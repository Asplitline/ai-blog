> **统计窗口**：2026-10-16（上周五）至 2026-10-23（本周五），Asia/Shanghai。来源为 [GitHub Trending](https://github.com/trending)、[10/22 七日榜单快照](https://githubtrending.today/weekly/)及仓库 Commit。滚动七日榜单与周五到周五口径略有不同；区分「本周代码变更」「本周重新受到关注」「延续研究」。

## 本周结论

本期不再按“项目逐个罗列”，而是按 Agent Engineering 的能力层整理。

本周最值得关注的变化有三条：

1. **Harness 开始进入“可优化、可比较、可回滚”阶段**：不只是写 Prompt，而是把 Skills、Memory、Tool Guidance、Plugins 等都纳入版本化实验。
2. **Context 开始从文本检索走向结构化证据**：代码 AST 图谱、可恢复压缩、来源分级逐渐成为独立工程层。
3. **Agent 产品正在补齐可验证执行链路**：Runtime 状态、工具 Evidence、Approval、独立 Eval 开始串成闭环。

## 一、Skills / Plugins：能力如何封装、分发和治理

### Claude Plugins

[anthropics/claude-plugins-official](https://github.com/anthropics/claude-plugins-official) 将 manifest、MCP、Commands、Agents、Skills 组织为可安装插件，并区分官方内部与第三方来源。

**本周变化**：security-guidance 升至 [2.0.16](https://github.com/anthropics/claude-plugins-official/commit/1e25068c)，扩展 Windows 证书库异常等测试场景。

**为什么重要**：Skills 正从“复制一份 Markdown”走向真正的插件治理问题：

- 来源是谁
- 当前版本是什么
- 依赖哪些 MCP / Commands
- 能申请什么权限
- 更新后是否破坏旧行为

**和此前项目的关系**：

- [cursor/plugins](https://github.com/cursor/plugins)：插件分发
- [Impeccable](https://github.com/pbakaus/impeccable)：Skill + 确定性检查
- [K-Dense Scientific Skills](https://github.com/K-Dense-AI/scientific-agent-skills)：领域 Skill Catalog

### Android Skills

[android/skills](https://github.com/android/skills) 按模型表现薄弱的 Android 开发任务维护 SKILL.md，并支持 Android CLI 与 Agent 插件。

本周 [v1.0.16](https://github.com/android/skills/commit/95ea931a1ad8f9b2be132ae0cfb2aad964d71118) 和 [Codex 插件修复](https://github.com/android/skills/commit/09a35383) 展示了跨宿主维护问题。

**值得学什么**：不要只研究 Skill 内容，重点看 Skill 如何被不同 Agent 宿主加载、版本化和兼容。

**本类学习优先级：P1**

## 二、Harness：Agent 行为如何被组织和持续优化

### Harness²

[google-research/harness2](https://github.com/google-research/harness2) 是本期最重要的 Harness 项目。

它将 Agent Harness 拆成八类可编辑组件，包括：

- system prompt
- guardrails
- memory
- tool guidance
- subagents
- skills
- scripts
- plugins

任务内通过 **Propose → Probe → Compose** 生成、试运行、组合改进；跨任务把经验写回 Improvement Harness。

**为什么重要**：Harness 第一次真正变成可以做实验的工程对象，而不是散落在 system prompt、rules 和 README 里的配置。

可以开始测：

- 成功率
- token 成本
- 延迟
- 失败类型
- 哪个组件改变导致结果变化
- 是否值得保留 / 回滚

**和此前项目的关系**：

- [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)：插件式执行
- [OpenRig](https://github.com/mvschwarz/openrig)：多个现成 Coding Agent 的编排
- [Superpowers](https://github.com/obra/superpowers)：人工设计的工程流程 Skill

Harness² 更接近：**如何根据执行证据持续优化整个 Harness**。

**下一步**：固定模型和任务集，只改变 Harness Version，比较结果。

**本类学习优先级：P0**

## 三、Context / Knowledge / Memory：Agent 到底看到什么

这一层建议继续拆成三个不同问题：

- Context Retrieval：去哪找
- Context I/O：什么能进入模型
- Memory：什么跨任务保留

### Graphify：代码结构 Context

[Graphify-Labs/graphify](https://github.com/Graphify-Labs/graphify) 使用 tree-sitter AST 提取导入、调用、继承等关系，建立可查询代码图。

关系边会区分：

- EXTRACTED：直接从代码提取
- INFERRED：推断得到

并支持 query、path、explain。

**本周变化**：10/21–22 的提交改进 SQL 表跨文件合并、T-SQL 解析、MCP 模糊查询和跨仓库调用证据定位。

[SQL 修复](https://github.com/Graphify-Labs/graphify/commit/b8d9f123) · [MCP 修复](https://github.com/Graphify-Labs/graphify/commit/c6d4c251) · [跨仓库定位](https://github.com/Graphify-Labs/graphify/commit/775ddb9d)

**为什么重要**：Coding Agent 不再只是全文搜索，而是可以围绕“API → Hook → Component”这样的结构关系取上下文。

**和此前项目的关系**：

- [PageIndex](https://github.com/VectifyAI/PageIndex)：长文档结构检索
- [code-graph-rag](https://github.com/vitali87/code-graph-rag)：代码图谱
- [Hindsight](https://github.com/vectorize-io/hindsight)：长期学习记忆

Graphify 更偏 **代码结构知识图 + 来源解释**。

### Headroom：Context I/O 压缩

[headroomlabs-ai/headroom](https://github.com/headroomlabs-ai/headroom) 压缩日志、JSON、源码和 RAG 内容，并通过 CCR 在本地保留原文，必要时恢复。

本周 [10/17 Turn Hook](https://github.com/headroomlabs-ai/headroom/commit/fbf7bc32) 支持 OpenAI Responses HTTP/WebSocket 请求改写；[10/16 计量提交](https://github.com/headroomlabs-ai/headroom/commit/2912b7b6) 开始记录每请求节省量。

**为什么重要**：Context Engineering 开始具备明确指标：

- token 节省
- latency
- 关键错误行保留率
- recovery 次数
- 最终任务成功率

**和此前项目的关系**：

- [context-mode](https://github.com/mksglu/context-mode)：过滤工具输出
- Headroom：压缩并支持恢复
- Hindsight：长期记忆

三者不是同一种能力。

**本类学习优先级：P0 / P1**

## 四、Runtime / Execution：Agent 如何真正执行任务

### Orca

[stablyai/orca](https://github.com/stablyai/orca) 提供 Coding Agent 的 Task、Run、Worktree 与 Review。

本周继续修复：

- [Session Resume](https://github.com/stablyai/orca/commit/f0450469)
- [审批状态](https://github.com/stablyai/orca/commit/1ac2c6a8)
- [Workspace 休眠](https://github.com/stablyai/orca/commit/41661e33)

真正值得研究的是状态机：

```text
queued
→ running
→ waiting_approval
→ resumed
→ completed
```

以及 workspace 的 sleeping / resume。

**为什么重要**：Agent 平台做大以后，最先出问题的往往不是模型，而是任务状态恢复、审批中断、事件顺序和重试。

### Ruflo

[ruvnet/ruflo](https://github.com/ruvnet/ruflo) 本周扩展 [逆向分析插件](https://github.com/ruvnet/ruflo/commit/1b319145)，并补充 [安全修复](https://github.com/ruvnet/ruflo/commit/92731bc6)。

这里更值得关注的是：通用 Harness 接入高权限领域工具后，Runtime 必须同时考虑：

- permission
- sandbox
- budget
- result trust
- audit

**和此前项目的关系**：

- OpenShell：执行隔离
- BrowserSkill / Mobile MCP：浏览器和移动设备 Runtime
- Coder：开发环境 Runtime
- Orca：Coding Agent Run 生命周期

**本类学习优先级：P1**

## 五、Control Plane / Approval：任务如何被治理

本周没有出现一个完全新的大型 Control Plane，但已有项目之间的边界更加清晰。

继续使用以下知识图：

- [Paperclip](https://github.com/paperclipai/paperclip)：组织、目标、预算、治理
- Google AX：Agent Workload 调度
- Cloudflare OS：Capability + Simulation + Async Approval
- OpenRig：本地多 Coding Agent Team 编排
- Orca：单个 Run / Workspace 状态

可以把它们理解成不同层：

```text
Organization / Goal
        ↓
Task Scheduling
        ↓
Run Lifecycle
        ↓
Permission / Approval
        ↓
Tool Execution
```

**本周建议**：不再新增 Control Plane 项目，先把这几个系统的职责边界画清楚。

**本类学习优先级：P1**

## 六、Evaluation / Evidence / Provenance：结果如何被证明

### REA

[morluto/rea](https://github.com/morluto/rea) 通过 MCP / CLI 暴露 JavaScript、Android 和原生程序分析，并明确返回：

- Evidence
- Coverage
- Limitations

本周改进 [不可变证据读取](https://github.com/morluto/rea/commit/74ed67da) 和 [ADB 解析](https://github.com/morluto/rea/commit/15ec8e98)。

**为什么重要**：Agent 输出不应该只有“我认为修好了”，而应该附带可验证证据。

例如：

```text
Finding
→ Evidence Ref
→ Coverage
→ Limitation
→ Independent Check
```

**和此前项目的关系**：

- [Atlas](https://github.com/pacifio/atlas)：Session → Git Commit Provenance
- Cloudflare Security Audit Skill：独立验证
- [iFixAi](https://github.com/ifixai-ai/iFixAi)：Agent 黑盒审计
- [tester-army/e2e](https://github.com/tester-army/e2e)：Agent 探索 → 确定性回归
- REA：工具执行证据

这几类项目共同构成 Agent 的 **Verification Layer**。

**本类学习优先级：P0**

## 七、Gateway：模型、工具与策略如何统一接入

本周 Gateway 没有出现必须新增的 P0 项目，重点继续巩固现有分类。

### Model Gateway

- [LiteLLM](https://github.com/BerriAI/litellm)
- OmniRoute

负责：

- provider routing
- fallback
- quota
- token / cost
- provider abstraction

### Tool Gateway

- [Treg](https://github.com/superdesigndev/treg)

负责：

- tool discovery
- API Key / OAuth
- permission
- audit
- bundles

### Policy / Capability Gateway

- OpenShell
- Cloudflare OS Gatekeeper

负责：

- capability permission
- secret injection
- approval
- policy verification

不要再把“Gateway”理解成一个单独产品类别，而是三类不同 Gateway。

**本类学习优先级：P2，本周以架构梳理为主。**

## 八、Local Inference：本地模型执行层

本周没有出现足以改变现有判断的新项目。

继续保留：

- [llama.cpp](https://github.com/ggml-org/llama.cpp)
- [Ollama](https://github.com/ollama/ollama)
- [vLLM](https://github.com/vllm-project/vllm)
- Magnitude
- llmfit

现阶段不建议把大量时间投入“再研究一个本地推理框架”。

更值得做的是：

```text
Agent Task
→ Model Router
→ Local / Cloud Model
→ Quality / Latency / Cost
```

把 Local Inference 当作 Agent Runtime 的一个可替换 Provider。

**本类学习优先级：P2**

[HKUDS/CLI-Anything](https://github.com/HKUDS/CLI-Anything) 本周继续出现在榜单，延续“把现有软件封装成 Agent 可调用 CLI”的方向。

这条路线和近期的几个项目可以放在一起：

- CLI-Anything：软件 → CLI
- BrowserSkill：浏览器 → Agent Runtime

- Univer：Office → Agent Runtime

共同趋势是：

> 不一定重新做一个 AI App，而是把成熟软件的已有能力重新暴露成 Agent 可调用接口。

**本类学习优先级：P2**

## 十一、周末实践：10 月 24–25 日

### 周六：Context + Evidence

**目标**：回答“Agent 为什么得到这个结论”。

1. 45 分钟：阅读 Graphify 的 AST 与来源标签
2. 60 分钟：在 React 项目追踪 3 个 API → Hook → UI 问题
3. 45 分钟：比较原始 Context、Headroom、context-mode
4. 30 分钟：输出 `graph-evidence.json` 和 `context-ab.md`

验收标准：

- 每个结论有源文件位置
- EXTRACTED / INFERRED 可区分
- 压缩后关键错误信息没有丢失
- token / latency 可比较

### 周日：Harness + Runtime + Evaluation

**目标**：回答“Agent 这次运行为什么成功或失败”。

1. 45 分钟：运行 Harness² Demo
2. 60 分钟：同任务比较两个 Harness Version
3. 45 分钟：加入 Evidence Ref / Coverage / Limitations
4. 30 分钟：加入 Pending Approval 和 Run State

最终输出：

- `runs.jsonl`
- `harness-diff.md`
- `evidence.json`

验收标准：

- Run 可重放
- Harness Version 可追踪
- Approval 状态可恢复
- 每个结果有证据
- 成本和质量可比较
